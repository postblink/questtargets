# Quest Targets 1.7.2

- The RareScanner button reads candidate coordinates from the Explorer's spawn markers, active overlays and saved sightings. It ranks each candidate by its closest projectable point, with QuestieDB distance and alphabetical order as fallbacks.
- The shared click path and the RareScanner button sample player coordinates before building the secure targeting macro. Coordinates and sorting stay in Lua. Search pages restart after the player moves and advance on stationary clicks.
- The targeting UI renders updated rankings after a click changes the position revision. Login, quest refreshes and periodic polling use cached coordinates. The current RestedXP guide step determines its own target order.
- Regression tests cover RareScanner coordinate sources, short moves, stationary macro paging, the ItemTree click path and the absence of player coordinate reads during background updates.
